## 2026-09-26 — Claim.MD sandbox API statuses are not X12 acknowledgments

The Phase 4 source path adds a separate Demo-only, default-off Claim.MD HTTP transport. Its
fixed API host and server-resolved account-key reference never cross the desktop boundary.
The connector validates test 837P and returned CLM01/D9 identities, retains bounded upload
XML encrypted with the immutable attempt, and never retries an uncertain upload. A second
worker reads Claim.MD status XML and ERA listings with distinct account-scoped cursors. Status
`A` maps conservatively to received, not payer-adjudicated; `R` requires claim-level review.
ERA listing pages are collected before processing in ascending ID order, with a bounded page
limit and duplicate-ID refusal. Processing only the first page could permanently skip older ERAs
if Claim.MD returns later-numbered IDs first.
Status receipts, matches, observations, and checkpoint commit atomically. ERA details are X12
835, so the connector invokes the existing `ClaimResponseIngestion` matching/payment owner and
atomically commits its encrypted receipt, financial effects, and ERA checkpoint. No connector
decides billability, correction eligibility, or financial settlement independently.

Claim.MD's API does not return 999; 277 is SFTP-only. The existing 999/277CA manual/mock intake
remains for other channels, but it is not fabricated as Claim.MD API output. A filename from
`uploadlist` is not proof of the exact uploaded bytes: its inbound ID and file count do not
provide a content hash, so unknown/Sending dispatches remain blocked pending a verified
reconciliation workflow. The unapplied Phase 2 migration, actual account provisioning,
single-worker/rate coordination, vendor variant tests, and end-to-end sandbox evidence remain
activation gates. No Claim.MD account/API call, secret configuration, migration, or deployment occurred here.

**Rejected:** treating HTTP 200 as claim acceptance, mapping Claim.MD `A` to payer approval,
inventing API 999/277CA files, sharing a status/ERA cursor, advancing a cursor before receipt
effects commit, advancing past an unread ERA listing page, retrying an unknown upload, and
automatically resolving a dispatch by filename.
