# DEC-0234 — Known-unsent account preflight recovery proposal

**Date:** 2026-10-09. **Status:** proposed; policy and additive source schema await Josh's review.
**Authority:** Josh requested worker isolation for queued claims with missing keys. The current
agenda permits local design/reproduction; BACKGROUND_WORKERS_HANDOFF §8 requires schema approval.

## Proposed choice and reason

Use one durable account readiness owner, separate from immutable dispatch/delivery evidence.
A valid account's typed missing key before Sending defers that account's queued work, allowing
other eligible accounts to be selected. Propose four persisted delays (1/5/15/60 minutes plus
bounded deterministic delay), then a fifth-failure hold requiring explicit scoped Admin reopen.
Successful due preflight resumes ordinary current release validation. Shared receipt-key,
SQL/lease, cancellation and unknown failures are not account faults. Sending/OutcomeUnknown
and actual receipt evidence retain their reconciliation owner and cannot be automatically resent.

The [canonical W8 proposal](../../../BACKGROUND_WORKERS_HANDOFF.md#october-9--known-unsent-dispatch-isolation-proposal)
owns exact fields, classification, lock order/staging, safe visibility/reopen, migration/rollback
and required fail-first acceptance. [Working evidence](../../readiness/work-evidence.md#2026-10-09--missing-key-dispatch-isolation-design)
records the bounded two-agency/two-host reproducer and actual checks; it does not show a fix.

Reject Cancelling temporarily blocked due work, process-memory skip lists, per-dispatch-only
backoff that repeatedly probes the same failed account, catching broad exceptions as nonreceipt,
holding SQL over key/network I/O and activation with old workers that ignore readiness.
Immediate indefinite hold is an alternative with fewer automatic probes but requires manual
intervention even for briefly unavailable configuration. Unbounded retries preserve the current
starvation/busy-loop risk. Numeric defaults are an engineering proposal, not a payer requirement.

**Pending review:** recovery policy, schema and bounded implementation/source migration files.
No schema/model/migration, new route, runtime scheduling or readiness score changes are made by
this decision. Existing-database migration, cloud settings, real data, release/deployment and
provider calls retain separate authorization. Full fairness, budgets and operating proof remain.

**Supersession:** none until accepted; DEC-0230–0233 and earlier W8 policies stay in force.
