# DEC-0236 — Activity-bounded Demo dispatch scheduling proposal

**Date:** 2026-10-09. **Status:** proposed; source inventory/design complete, policy review pending.
**Authority:** Josh requested the next agenda item after release 1.3.39. SATI-WRK-001 authorizes
the idle/wake/activity/due design slice, not implementation of a new runtime cadence or activation.

## Recommendation and reason

Use one API-owned coalesced activity signal and the existing hosted dispatch loop. A bounded
startup catch-up, finite activity period, paced turns, relevant durable due times and active-only
reconciliation replace perpetual idle discovery in the proposed policy. Park without SQL after
activity expires; earliest due is not a guarantee of unattended delivery. Authoritative readiness,
leases, current billing checks and uncertain-send recovery retain their existing owners.

[The W8 scheduling proposal](../../../BACKGROUND_WORKERS_HANDOFF.md#october-9--dispatch-idle-wake-scheduling-proposal)
is the canonical owner of the exact numbers, allowlisted signal publishers, state transitions,
SQL/connection accounting, fake-time acceptance and operating tradeoffs. Do not copy its numeric
policy into another scheduler or infer physical user presence from an authenticated request.

Reject a longer perpetual idle SQL timer as sufficient protection, wake pings/client heartbeats,
health/renewal/telemetry as user activity, unbounded successful-loop draining, a second scheduler,
per-agency process-memory queue maps, local signals as distributed admission, and timer-driven
replay of Sending/OutcomeUnknown. A local hint is never billing approval or reliable event delivery.

**Dependencies:** explicit adoption before runtime changes; D1–D4; enabled compatible host/schema
versions; post-validation/post-commit publishers; typed turn outcomes and real hosted fake-time/
race/private SQL acceptance. Aggregate budgets, fair selection, dependency/operation bounds,
request admission, intended-host load and owner alerts remain separate activation work.

**Evidence and limits:** inventory at `d223b1736df18202e397cea53a328984c50c3416`, reviewed source
paths and [dated working evidence](../../readiness/work-evidence.md#2026-10-09--sati-wrk-001-dispatch-idle-wake-design).
No runtime tests, measured cloud capacity, database access or operating behavior change follows
from this design. The proposed tests are unrun; all sealed readiness scores remain unchanged.

**Supersession:** none. DEC-0235's accepted account readiness/recovery policy and D1–D4 remain
authoritative; this proposal fills its separate idle-cadence review dependency. A later acceptance
record must explicitly adopt/amend the concrete policy without rewriting retained reasoning.
