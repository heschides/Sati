## Choice and reason

`Sati.Contracts.V1.OriginalClaimReleaseRules` owns original generation/queue/pre-Sending delivery
permission. `Sati.Persistence` owns `OriginalClaimReleaseHistory` and the common relational
history loader. API and transitional local adapters establish trusted scope and map their
distinct note/claim/generation models. They scan all modes and historical accounts for the same
agency/NoteId business claim; fresh request keys, controls and namespaces do not create a new claim.

Retained controls, complete CLM01, single REF6R, historical D9/account identity, exact correction
links/frequency/F8 and predecessor mapping are verified. The shared parser now exposes F8.
Damaged physical/uncertain history remains a hold; unused Generated-only files do not prove
delivery. Query caps return incomplete, never empty authoritative history. No current-enabled
flag hides a historical account. Protected response bodies and secret references are excluded
from the common projection reads.

Queued originals reserve against fresh originals/new queue intents. Sending, unknown and generic
rejection hold. Accepted uploads, including all-R results, and exact receipts require explicit
eligible correction lineage. Audited nonreceipt is correlated to exact dispatch/account/hash/
claim identities, revision and prior uncertain state; later exact receipt wins. Named event
semantics replace ordinal inference in this projection. Unscoped delivery events hold their
known period, or the agency when scope cannot be established.

Apply sequential checks at API/local fresh original generation, API new queue and worker
immediately before Sending. Preserve exact result/intent replay and current original export
compliance. A refused queued worker candidate becomes CancelledBeforeSend with a safe hold code
and no upload attempt. Existing correction-action permission remains with `ClaimCorrectionRules`.

## Evidence, rejected alternatives and limits

[The runbook](../../../CLAIMMD_SANDBOX_RUNBOOK.md#sequential-delivery-history-guard--local-source-october-9-2026)
owns behavior and the remaining transaction work. [Working evidence](../../readiness/work-evidence.md#2026-10-09--original-delivery-history)
records actual fail-first API/local results, legitimate recovery/correction positives and setup
failures. Fixtures use independent legitimate lifecycles instead of mode bypasses or repeated
raw originals after receipt. Silently skipping malformed history, trusting only the newest row,
treating upload rejection as nonreceipt and inventing missing account provenance are rejected.

This is sequential admission evidence. The existing transaction owners do not coordinate all
history writers. Common SQL admission, worker source refresh, mock admission, staged wrapping,
poller single-attempt ownership, recovery cleanup, deterministic SQL races and full R2 current
exact-subset compliance/correction-purpose revalidation remain required. No migration, external
provider action, deployment, full R1/R2 closure or readiness score change is established.
