# DEC-0221 — Standing documentation upkeep and bounded next-work invocation

**Date:** 2026-10-08. **Status:** accepted. **Authority:** Josh requested standing Markdown
instructions for thorough updates after each significant work portion and the easy phrase
`Perform the next thing on the list` to continue the prioritized work.

## Context and choice

Use AGENTS.md as the canonical workflow owner. Significant work updates its affected topic
owners, current backlog/status/dependencies, durable decisions when needed and dated working
evidence before completion. Indices link those owners; they do not repeat policy or mutable facts.
The agenda has one explicit next eligible stable-ID pointer, with a bounded slice, dependencies,
acceptance evidence and authority. The initial concrete slice is per-agency recoverable-failure
isolation in NoteAbandonmentWorker, with fail-first synthetic tests. The preceding documentation
audit already covered W8 intake/fairness gaps; repeating its matrix is not the next implementation.

The entire trimmed phrase, compared without case sensitivity, invokes that eligible bounded
local slice. A discussion, quote or instruction about adding the phrase does not invoke it.
The assistant reads the owners, revalidates dependencies, announces concrete scope and expected
verification, proceeds within existing authority, and updates the pointer and documentation
before reporting completion. Blocked work receives an explicit reason and an eligible successor
where one exists; unfinished work does not disappear.

## Alternatives and consequences

Manual reminders leave upkeep dependent on conversational memory. A bare first unchecked item
could select superseded historical work or an unbounded project. Stable current IDs, explicit
eligibility and evidence make continuation concrete and reviewable.

The phrase keeps release/DATT, deployment, publication, cloud, database, real-data and external
action permissions separate. A valid future next-work invocation authorizes only the listed
reversible local worker/test change and synthetic disposable local tests. Preserve the global
SQL/reset locks, 100-note bound, guarded revisions, atomic audit, default-off and hourly cadence.
Healthy B progresses after a narrow recoverable A-scoped fault; A remains due and is attempted
once per pass, with cancellation and fatal/shared failures propagated. No worker activation,
schema change, live-data access, provider send or deployment is authorized. This documentation
task does not invoke the phrase or implement that worker change. Working
evidence is dated separately from sealed release snapshots; it never rewrites a prior release
score, rubric or observed activation state.
