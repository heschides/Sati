## Choice and reason

Persistence `ClaimReleaseWriteScope` owns the first agency-scoped, transaction-owned exclusive
SQL admission lock. Existing period/service-time scopes acquire it before their narrower locks.
Generation, correction, queue, worker Sending/result, reconciliation, mock transmission and
manual/status/ERA receipt decisions read current facts inside that boundary. Failed write
recovery disposes the failed transaction, clears tracked state and starts fresh admitted reads.
Direct receipt/local paths own a zero-retry execution scope; direct receipt and dispatch paths
refuse retrying outer callers before I/O. An uncertain commit never authorizes automatic upload.
Cancelled SQL admission retains the caller token without exposing a provider payload. Known
contention maps to a safe conflict for lazy GET reconciliation as well as ordinary commands;
ordinary read execution retains its existing retry behavior.

Key wrapping happens outside SQL admission. Receipts reserve their identity for encryption
binding, then repeat authority/account/cursor/duplicate/matching checks in a fresh transaction.
Exact replay and stale-feed no-op occur before wrapping and survive unavailable keys. The worker
prepares keys before admission, reloads account/file/intent after admission, commits Sending,
releases SQL, uploads once and retains the actual outcome under fresh admission. Receipt-first
holds a successor; Sending-first retains both facts because a committed upload cannot be unsent.

API current release validation reuses `BillingExportGate` and service-date compliance policy for
the exact validated retained claim subset. Original and Resubmit/Replace require current positive
billability at new queue and immediately before Sending. Void withdraws an existing standing bill:
loss of positive billability must not prevent that withdrawal. Exact identity, current correction
action/payer number/predecessor, agency/period and amendment financial review still apply to Void.
This preserves the existing correction purpose; it does not expand payer or operator authority.

Correction history uses the shared validated delivery projection. Unused renders do not supersede
the delivered claim; damaged physical history and uncertainty hold. Generated corrections remain
pending. GET history is advisory; commands reload under owned admission and enforce the shared rule.
