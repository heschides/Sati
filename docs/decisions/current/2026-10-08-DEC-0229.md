**Date:** 2026-10-08. **Status:** accepted; the bounded SATI-SEC-001 health-error slice is
implemented and locally verified.
**Authority:** Josh's direct request authorizes completing the current worker, billing-export and

The completion handoff was followed by Josh's valid October 8 `Invoke DATT!` invocation, which
now authorizes the bounded actions in [the release playbook](../../../RELEASE_PLAYBOOK.md),

no schema migration; its local evidence does not establish deployment or release completion.

## Context and choice

Both actual health checks returned raw caught exceptions. The schema check also supplied its
exception directly to a logger. The matching
[ASP.NET Core 10.0.12 health service](https://raw.githubusercontent.com/dotnet/aspnetcore/v10.0.12/src/HealthChecks/HealthChecks/src/DefaultHealthCheckService.cs)
retains result exceptions/Data in report entries and passes exceptions to Unhealthy logging.
Generic anonymous HTTP text therefore leaves other release paths exposed. Eleven genuine
synthetic failures across three non-overlapping baseline runs identify these logger/result paths;
four positive controls preserve ordinary checks and pre-cancellation behavior.

Keep caught failures in `SchemaDriftHealthCheck` and `DatabaseIdentityHealthCheck` Unhealthy,
with fixed descriptions, no result exception and empty failure Data. The schema logger emits
only a fixed operation, bounded type and HResult. Framework Error/status records remain visible.
Preserve anonymous readiness 503/Unhealthy, known missing model-object details, healthy checks,
the real identity validator and its case-insensitive matching/mismatch/missing-marker outcomes.
Keep direct operation cancellation Unhealthy; framework pre-cancellation still invokes no probe.

## Alternatives and consequences

Returning only a generic HTTP response or hiding descriptions misses logger/report references.
Changing log levels hides health evidence without sanitizing retained result fields. Supplying a
replacement exception still gives consumers an exception payload they do not need. Rethrowing
cancellation would change the direct-check contract beyond this repair. These alternatives are
rejected. Remove the raw exception at its result source and retain fixed status observations.

No shared all-logger replacement or framework patch is introduced. `DatabaseIdentityHostedService`,
startup identity validation, check registrations, routes, authorization and schema remain unchanged.
Registration construction, other checks, failing loggers, independent EF/provider diagnostics,
startup identity logs and callback/host paths need their own evidence and future decisions.
