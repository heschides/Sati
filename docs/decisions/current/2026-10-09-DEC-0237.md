**Date:** 2026-10-09. **Status:** accepted; bounded local source implementation.
**Authority:** Josh requested continuation immediately after the concrete DEC-0236 proposal and
its review/adoption next step. The implementation turn explicitly treated that continuation as
adoption of the presented policy. Existing ordinary commit/push authority applies; no DATT,
deployment, migration, cloud setting or dispatch activation was requested by this continuation.

## Decision and reason

Adopt the exact activity, pacing, due and cooldown policy retained in
[the canonical scheduling policy](../../../BACKGROUND_WORKERS_HANDOFF.md#october-9--dispatch-idle-wake-scheduling-proposal).
`ClearinghouseDispatchSchedule` is the sole local scheduling owner; the existing worker returns
typed turn outcomes and a scalar empty-queue snapshot. Validated existing handlers publish
coalesced hints after successful work, with queue/reopen transaction and lease disposal preceding
notification. Eligibility, audit, account/reset/dispatch leases and uncertain-send rules remain
authoritative in their existing owners. No client heartbeat or durable event infrastructure is added.

The inactivity tradeoff is accepted: overdue work may wait for qualifying use or a host restart,
and successful work does not renew activity. This preserves dormant Demo capacity rather than
creating an unattended delivery promise. The retained proposal's rejected alternatives and
aggregate SQL/connection accounting still apply. A local signal grants no billing authority.

**Dependencies and limits:** default-off Demo/Testing gate; compatible approved readiness schema
and host versions; existing publisher identity/scope checks. Broad W8 fairness, aggregate budgets,
request admission, query plans, intended-host load and owner alerts remain activation requirements.
The local pacing bound is not a global resource or fair-wait guarantee. Cloud Production needs a
separate reviewed durable wake/service policy.

record actual unfixed-code proof, synthetic fake-time/API/private SQL acceptance, failures and limits.
Working evidence changes no sealed release report or rubric.

**Supersession:** supersedes only DEC-0236's pending adoption/implementation status. Its dated

in force; this decision authorizes no activation or operational release.
