# DEC-0239 — Hierarchical dispatch fairness proposal

**Date:** 2026-10-09. **Status:** proposed; task 1.3.1 design awaiting review.
**Authority:** Josh requested 1.3.1's bounded source inventory/design. This record recommends a
policy and additive source schema for review; it does not adopt them or authorize implementation,
an existing database migration, activation or deployment. Ordinary documentation commit/push
uses standing user authority independently of this proposal.

## Proposed choice and reason

Recommend persisted agency-first round robin, account rotation inside the agency, and oldest
Queued dispatch inside the account. Advance an offer before attempting lane admission so known
contention does not select the same head indefinitely. A short shared SQL selector transaction
serializes cursor changes across hosts; release it before current dispatch/account/claim-release
admission and dependency work. Scheduling metadata belongs in Persistence and the sole API
selection owner, independently of account/readiness business revisions and physical send evidence.

[W8's task 1.3.1 design](../../../BACKGROUND_WORKERS_HANDOFF.md#october-9--dispatch-fairness-design--task-131)
owns the complete source inventory, exact metadata/query/lock proposal, conditional A and A×K
offer bounds, restart/churn limits and deterministic acceptance plan. Do not duplicate or infer
numeric resource/latency guarantees from it. [The agenda](../../../AGENDA.md#next-eligible-work)
owns adoption and implementation ordering; task 1.4.1's separate inventory informs later budgets.

Propose a narrowly typed LaneSkipped result for known dispatch/account zero-wait misses or scoped
stale selection before Sending. Such a skip spends its offer and respects ordinary pacing while
active. Reset/selector/shared/unclassified failures keep the adopted shared cooldown. The typed
known-unsent missing key alone keeps its accepted readiness failure handling. All current
billing/compliance, cancellation, default-off, inactivity, uncertain-send and reset rules remain.

## Alternatives and tradeoffs

- Global oldest-first preserves backlog order but lets one agency's old files or busy head consume
  the opportunities. Preserve ordering only inside a lane.
- Flat account rotation bounds lane visits in a stable roster but gives agencies with more
  accounts more offers; agency-first rotation better matches multi-agency isolation.
- Process-local cursors avoid schema work but lose position on restart and produce independent
  host phase bias. Per-agency dictionaries also need a separate capacity/lifecycle policy.
- One global lock through upload serializes dependency delays across agencies. The proposed lock
  protects only a bounded selection transaction; existing record/account leases protect sends.
- Weighted or deficit scheduling needs adopted weights and measured operation costs. Dedicated
  queues/hosts need separate quota, wake and infrastructure choices; defer them to budget evidence.

Persisted cursors introduce a shared short write, an additive metadata/index migration proposal,
and one retained cursor per offered agency. That is not a storage quota or aggregate admission
policy. Offer advancement can survive a crash without producing a send, so offers are never
receipt/nonreceipt evidence. Stable-cohort turn bounds exclude dependency outages, target lease
unavailability, dormant hosts, infinite membership churn and incompatible workers. No measured
capacity, wall-time bound or current operating acceptance is established.
