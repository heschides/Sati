## Decision and scope

Adopt the [canonical hierarchical fairness policy](../../../BACKGROUND_WORKERS_HANDOFF.md#october-9--dispatch-fairness-design--task-131):
persisted agency-first/account rotation, oldest-in-lane selection, one committed offer per turn,
short shared SQL selector released before existing send admission, and typed LaneSkipped for
positively identified dispatch/account zero-wait misses or stale work before Sending.
Preserve shared cooldown for reset/selector contention and shared/unknown errors, current
activity/pacing/startup rules, accepted readiness recovery and all billing/uncertainty controls.

Persistence owns the approved additive cursor entities/configuration/migration and Queued-lane
index; the API's constructor-injected selector owns short zero-retry cursor writes. Existing
business revisions and immutable evidence remain independent. The source-grounded design retains
alternatives, conditional offer bounds, membership/dependency exclusions and acceptance cases.
No throughput, wall-time, aggregate budget, vendor quota or operating guarantee is adopted.

Task 1.3.2 implements and proves this bounded dispatch change with fail-first local tests and
private synthetic SQL ownership/restart/rollback/inactivity acceptance. Task 1.4.1 stays with
the second investigation thread. Other-worker fairness, resource budgets, API admission and
load/alert activation retain their separate owners and dependencies.

**Evidence:** [working ledger](../../readiness/work-evidence.md) and [the agenda](../../../AGENDA.md#next-eligible-work)
record the current implementation/acceptance status. Source generation changes no existing
database; apply, baseline/reset, rollout/rollback, deployment and activation remain separate.

**Supersession:** supersedes DEC-0239's pending adoption/source-schema approval status and only
DEC-0237's blanket cooldown for positively identified local dispatch/account lane misses.
DEC-0237's shared-failure, activity, pacing, startup and inactivity rules remain. DEC-0235,
D1–D4 and existing physical send/reconciliation safety are unchanged.
