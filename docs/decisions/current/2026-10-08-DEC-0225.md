# DEC-0225 — Note-worker completion cache follows the local day

**Date:** 2026-10-08. **Status:** accepted for the fourth bounded local SATI-WRK-001 slice.
**Authority:** Josh requested remaining eligible work in sequence with ordinary verified
commits/pushes to the approved repository/branch. The agenda selected stale-day completion-cache
retention. This is local source/synthetic authority, not DATT, activation or a release.

## Context and choice

The note worker's `completedByAgency` dictionary retained successful agency IDs and dates across
all prior days. Bounded agency discovery did not retire removed agencies or that storage.
The regression completed 251 zero-note agencies, removed 150 and added ten on the next local day,
then left one current agency due. The original cache retained 261 entries instead of the expected
110 current-day successes.

Track `completionCacheDay`. In `RunDueAsync`, after the existing enabled check and `runGate`
acquisition, capture `ApiClock.Today`. If it differs from the cache day, replace the dictionary
and record the captured day before evaluating `allCompletedOn`. All completion writes use that
same captured date while the gate is held, so the dictionary contains only successes recorded
for its current captured day. Retain current-day successes across recoverable/at-limit retries.

Replace storage rather than only clearing/removing old entries, so earlier populations' backing
storage is no longer retained by this worker. This is a source ownership choice; garbage
collection and measured process-memory use are not established by the cardinality test.
Rotation happens on an enabled call that acquires the existing gate. Disabled or already-canceled
calls do not open SQL or add an idle cleanup scheduler; earlier storage can remain until that check.

Keep global successful-day skipping, next-local-day catch-up, the distinct 100-agency discovery
and 100-note sweep bounds, finite-range membership limits, classified failure continuation,
atomic audit/committed-count rules, SQL/reset leases, cancellation/disablement and default-off/
hourly/no-idle-SQL cadence. Change no route, schema, authoritative business rule or dispatch policy.

## Alternatives and consequences

Keeping the lifetime dictionary leaves historical retention. Clearing or pruning entries alone
does not retire the old backing capacity. Imposing a 100-entry cap would confuse discovery-page
size with completion bookkeeping and could discard same-day skips/repeat completed work.
Evicting current-day successes on every pass would likewise lose partial progress. Adding a
timer, SQL cleanup or durable completion records would enlarge the scope and its dependencies.

This retires historical cache ownership after a captured date-change check, not current-day
cardinality/churn, completed agencies removed during the same day, immediate garbage collection
or a measured memory maximum. It does not invalidate completed-day membership for newly
provisioned agencies, introduce restart durability or prove total-pass/healthy-agency wait bounds.
Those W8 limits remain explicit; earlier DEC-0224 membership caveats still apply.
