# DEC-0227 — Contain escaping API request exceptions

**Date:** 2026-10-08. **Status:** accepted for the bounded SATI-SEC-001 request-boundary slice.
**Authority:** Josh's direct remaining-work request authorizes verified reversible local source,
tests, documentation and ordinary commits/pushes to the approved repository/branch. No DATT,
deployment, live-data access, schema or cloud/security change is invoked.

## Context and choice

The real Program pipeline's `UseExceptionHandler` delegate returned a generic response but passed
an unrestricted exception to its logger. Framework handling also published raw diagnostic
payloads; after a response starts or error handling fails, raw failure data could reach hosting.
Fail-first synthetic requests observe those sinks directly, including safe-message `Data` leakage.

Replace that registration with constructor-injected `ApiExceptionBoundaryMiddleware`, first in
the explicit pipeline. Catch escaping downstream request exceptions without replaying the request.
Log fixed operation, bounded type, HResult and server correlation ID only. Keep the existing
best-effort `ApiIncidentRecorder` safe-envelope path. Return generic 500 with correlation,
security and no-store headers when writable; contain and abort a started response or secondary
failure. A cancelled request's operation/I/O exception keeps 499 without an incident, while an
unrelated cancellation exception remains an unexpected failure.

## Alternatives and consequences

Response-only assertions and a log-level change miss raw exception references, structured state
and diagnostics. A suppression callback alone does not cover framework branches before it runs
or failing handlers. Removing only the application's raw log argument leaves framework exposure.
Re-executing a failing request could repeat durable or external work. These alternatives are
rejected. A new all-framework redaction architecture would enlarge this bounded repair and needs
its own enabled-sink inventory and fail-first proof.

The replacement removes exception-handler-specific framework events/metrics. Safe Error logs,
normal hosting HTTP observations and best-effort incident recording remain; the existing actor,
tenant and middleware order remains authoritative. The raw exception is available only locally
to the safe fingerprint/envelope owner within this path. Logger/store/response/abort failures
cannot replace the original response by escaping as a second raw exception.
