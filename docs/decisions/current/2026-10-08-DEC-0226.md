## Context and choice

`BillingExportGate.Evaluate` documented `complianceErrors` as the caller's authoritative
service-date result after exact-obligation supervisory exceptions and Admin recovery. Its source
nevertheless appended that list only when neither the frozen claim nor live source had an
exception. A complete matching PCP exception could therefore discard an unrelated assessment
blocker, including one created by revoking an attestation after a file was retained.

Always append the caller's remaining errors after the existing source/exception provenance
checks. Preserve ordinal deduplication and the shared owner in `Sati.Contracts.V1`; both API
original export/replay and transitional local EDI release continue to call it. The caller resolves
service-date policy, exact selected obligations and immutable recovery evidence. The export gate
checks frozen agency/person/date, current approval, supported configuration and matching stored
approval; it cannot grant a new exception or remove an error that survives the caller's decision.
Form-work deadlines remain separate non-waivable caller checks.

Correct the two older positive export fixtures to retain actual selected PCP obligation IDs and
explicit attestation confirmation. Add real API/local attestation-revocation cases for fresh keys
and exact replays, and positive exact Admin recovery through the existing real recovery owners
before staging the frozen claim. No source claim, file, exception, recovery record or audit is
rewritten to make a refusal pass.

## Alternatives and consequences

A blanket exception bypass contradicts exact-obligation authority and hides newly applicable
or withdrawn obligations. Re-evaluating a second compliance decision from today's mask would
diverge from service-date policy and could block legitimate recovery. Copying another gate into
the API or local service creates two authoritative versions. Removing approval/provenance checks,
weakening recovery or altering frozen financial content would enlarge the repair and is rejected.

Keep the single rule and existing caller evaluations. Returning retained bytes remains an export
requiring current authority and residual compliance checks. Legitimate exact exceptions and Admin
recovery continue when the authoritative result is empty. The changed code grants no broader
supervisory waiver, transport retry, correction permission, schema change or external-send authority.
