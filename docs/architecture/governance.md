# Preservation, retention and recovery

**Status:** current architecture reference, October 8, 2026. Detailed rules remain with the linked canonical owners.

Implemented source: scoped/versioned holds, independent release decisions, proposed policies and shared preservation-lock coordination protect connected decisions. Legacy holds remain retained. Consumer deletion has additional immutable-review/financial/preservation constraints.

Runtime retention remains PolicyOnly. Complete storage/dependency/backups/key recovery adapters, approved schedules, named operators and actual restore/alert evidence are required before enabling destructive work. A count-only synthetic/PITR script test is not proof of full-service restoration.
